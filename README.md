# Agent 应用开发实战课 · Java

用 Java 搭一个能提出行动、调用业务工具、读取观察、追问和有条件结束的 Agent。你会面对一个后端工程师熟悉、但引入模型后变得棘手的问题：外部服务执行确定的代码，提出下一步动作的模型却可能选错工具、读错结果，或者在失败后要求重复执行。课程教你如何把这两部分接起来，并逐层验证行为。

## 读完后的面试自测

合上正文，用三分钟回答这道陌生题。用户说“检查刚补交的商户资料，如果仍缺件就起草通知”。模型看过旧版本，读服务这次超时，而草稿服务在前一轮已经收到一次请求，是否写入未知。面试官再加一个条件：900 ms 内要给出首个有依据的反馈。你会怎样设计下一步？

可以用这些标准核对自己的回答：先区分用户授权起草与正式发送，确定核验对象和材料版本；读超时不意味着材料不存在，写回执未知也不意味着没有草稿；用稳定操作键核对已有草稿，具备幂等与时间预算才重试。若只能确认上次读取时间或某项操作仍待核对，就尽早交付该事实与未知范围。日志将模型轮、真实工具尝试、最终草稿数和首条正确事实的时刻分别记录。最后解释哪一段适合固定 Java 逻辑、哪一步确实需要模型决策，再给出一种能推翻当前设计的对照实验。把每项依据追溯到代码、输入或记录，便能继续应对追问。

## 运行第一课

**[打开第一天，跟着老师运行一次 Agent](lessons/week-01/daily.md)**。第一题已经给出地点，直接研究 Agent 如何行动。JDK 17+、Python 3.9+ 即可运行入门示例；压测探针需要 Python 3.10+。在仓库根目录执行：

```powershell
py -3 examples/agent-loop/run.py sun
py -3 examples/agent-loop/run.py early
py -3 examples/agent-loop/run.py wrong
```

第一条应先观察到周日时段，再提交关闭结论。第二条在还没查时就结案，第三条查到资料却判断错，读两次拒绝原因。Java 负责执行、状态、权限与预算校验，Python 负责读取快照和连接决策源。默认用脚本代替模型，确保可以调试同一条失败轨迹。第 1 周实验内提供真实模型的接入方式。

## 贯穿案例与毕业验收

- **场馆助理。** 公开资料支持核验、比较与说明来源。用户从“周六”改成“周日”时，哪些状态沿用，哪些事实必须重新验证？题目可以直接提供对象 ID。[场馆事实](data/hk-study-rooms/search-v2/README.md) · [跨类别开发样例](data/hk-poi/mixed-v1/README.md)
- **商户资料预审。** 用课内虚构的材料清单区分“读取、指出缺件、起草、正式提交”。写入均在本地练习环境。通过同一操作重试、材料诱导越权等题，检验运行时能否迁移到不同业务。[输入与参考判定](lessons/week-02/lab.md)
- **作品证据。** 至少演示一次观察改变下一步、一次澄清、一次工具故障、一次宿主拦截错误，以及一次同条件架构比较。交付代码、运行命令、成功和失败轨迹、逐题分母与尚未验证的假设。脚本回放和真实模型分开报告。

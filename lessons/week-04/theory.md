# 第 4 周 · 理论讲义｜用对照实验定位 Agent 的改进来源

## 老师精讲：给系统设计一个不会奖励错误行为的考试

先给“答对”下操作定义。用户要查地点时，返回正确 ID 可能就够了；用户要判断周日晚上能否前往，正确 ID 只是必要条件，还需正确的区域、时段与引用。若奖励函数只看出现“花园街”，它会奖励地址正确、营业时间错误的答复。把面向用户的目标拆成检索、证据、判断、生成四个观察点，能避免单一总分遮住这种错误。

开发题帮助修改方案；留出题帮助检验事先冻结的选择；回归题用于防止已修过的问题重现。这三个用途取决于题目是否被用于调试，和文件名没有关系。题量小时尤其值得保存逐题记录，查看同一题在两个方案中的转变。

### 算一个“总分没变”的例子

教学假设：固定流程在 A、B、C、D 四题上得 [对, 对, 错, 错]，动态方案得 [对, 错, 对, 错]。两者都是 2/4。逐题看，动态方案修复了 C，却让 B 退化；可能 C 属于消歧题，B 属于稳定直查题。与其简单宣布两者打平，可以分别读取 B、C 的首次分歧并提出分流假设，再用独立题验证。四题还不能证明路由收益；它们已经足以告诉你下一步该调查什么。

## 从一个错答开始

Agent 推荐周日 19:00 去花园街自修。这个错答可能对应四种故障：候选检索成了别家馆；取证查的是整栋图书馆；拿到了周六而非周日的时段；正确证据在上下文中却被模型读反。四种原因对应不同的修改。先保存候选列表、工具返回、最终引用及答案，再决定应该调检索器还是改执行逻辑。

## 两个实验和两个分母

**实验 A 测排名。** 固定地点、文本字段、开发题和标注，只改变关键词与混合召回。明确目标的题记录目标是否入前五；多候选题将意图相关性标成 0/1/2。若地点相关，只是尚未取得开放证据，保留它的检索相关性，另评时间条件。无可匹配项的题独立评估，避免把没有理想排名的题硬塞进 nDCG。

**实验 B 测任务完成。** 固定混合检索器、证据集、生成模型、每题 3 次工具预算和相同输出要求。比较固定流程与按需查证是否答对。给两者相同预算上限，实际用掉多少单独记录。固定流程也必须有能力取得正确证据，否则实验只检验了谁能访问材料。

**手算一例。** 教学排名的相关度为 [1,2,0]。取增益 `2^rel−1`、位置从 1 起，DCG@3 为 `1+3/log2(3)≈2.893`；理想排序 [2,1,0] 得 `3+1/log2(3)≈3.631`，比值约 0.797。指标惩罚关键结果排在后面。模型最后有没有误写营业时间要另外判。

## 让判分标准承认“未知”

逐条判断简介中的可核实事实。引用存在只说明链接可访问，还要核对分馆、时段和服务区域。题目要求无法从资料确认的设施时，说“资料未说明”合理；资料明确写了时段却仍答未知，计漏答。技术故障导致无法完成任务，记端到端未完成并另报故障数。

**自检。** 在 8 条留出题上多答对 1 条，该怎么报告？写“两方案各通过几题/8、哪一题从错变对、哪题退化”，易波动的案例保留 3 次运行。这个样本适合检查设计与失败机制，大范围提升需要更多独立查询。[Anthropic 的 Agent 评测实践](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)

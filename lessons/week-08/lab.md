# 第 8 周 · 实践讲义｜怎样把一次演示变成可复现的工程作品

## 从干净目录复跑（8 小时）

1. **2 小时，写复现说明。** 在你的作品分支记录 JDK/Maven 版本、启动入口、名录与证据快照、模型配置和环境变量名。列出离线回放与真实模型的两种运行方式。用实际命令替换文档中的示意命令；无凭据时要明确哪些步骤只能回放。
2. **2 小时，隔离运行。** 克隆到新目录，按说明构建。先执行离线测试；再用配置好的模型执行一题。对照两次输出的目标编号、事实来源与是否正确，不要求用词逐字一致。保留提交号和日志。
3. **2 小时，复测新题。** 准备至少 4 道此前未用于调参的查询，覆盖至少两类意图。固定参考时区、输入、程序和资料版本，先写独立参考答案，之后一次性运行。把“8 条既有留出题”和“第 8 周新题”分开报告。
4. **2 小时，练 8 分钟演示。** 计时演练，抽查任一事实能否在一分钟内定位到本次取回的来源。把最能体现设计取舍的一页放在作品首页。

| 演示时间 | 展示什么 |
| --- | --- |
| 0–1 分钟 | 用户问题与名录字段，指出为何时间条件需要另一份资料。 |
| 1–3 分钟 | 跑名称直查和普通周末时段两题，展示工具轨迹差异。 |
| 3–5 分钟 | 演示改问星期或分馆，用证据卡说明为什么答案改变。 |
| 5–7 分钟 | 展示一次真实失败、最早分歧步骤及修复前后回归。 |
| 7–8 分钟 | 展示逐题对照和成本，给出架构选择与数据适用范围。 |

**自查清单。** 别人能从原始查询找到该题全部证据；不提供密钥也能回放已有轨迹；新环境真实调用的前提写清楚；样本数量、耗时、调用数和正确率都来自实际运行。第二位读者若卡住，记下具体步骤并修复说明。

**求职描述模板。** “在 __ 条公开地点和 __ 道独立测试题上比较 __ 与 __。对 __ 类请求，方案 A 多/少用 __ 次工具调用；在 __ 条上避免/引入 __ 类错误。当前尚未覆盖 __。”保留测得的负结果。第 9、10 周再把单请求的对照扩展为服务级压测。

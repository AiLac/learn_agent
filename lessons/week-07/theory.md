# 第 7 周 · 理论讲义｜任务规划、工具并行与子 Agent

## 一道必须保留两个结果的问题

“11 月普通周六 19:00，花园街和薄扶林哪家还能温书？”同一个比较维度，两个独立的证据对象。花园街到 20:00，薄扶林普通周六到 17:00，因此常规安排下只有花园街符合。如果薄扶林查询超时，你只能确认花园街符合，不能继续声称“只有”一家符合。[官方时刻表](https://www.hkpl.gov.hk/tc/locations/opening-hours-04.html)

**固定计划**可以先解析两馆，再分派两次只读查询，最后按同一时点比较。**单 Agent 动态执行**可以在第一份结果不足时换主题或请求澄清。**子 Agent 分工**允许每个分支有自己的模型交互与上下文，适合分支内部还要多步探索的任务。当前这道题如果工具参数已知，两个普通函数就能并行取得证据。额外模型只有在补充核验等能力真实有用时才值得引入。

## 计划、执行和汇总的协议

计划里至少要写任务标识、对象、完成条件和依赖。可并行的两馆查询共享相同的月份与时刻，各自返回来源、适用范围及状态。汇总方区分 `FOUND`、`NO_DATA`、`ERROR`，并检查预期的任务 ID 是否全部交回。否则先结束的分馆更容易出现在答复里，慢的那家会被误判成不符合。

顺序执行两个独立工具，理想化耗时约为 `A+B`；并行等待两者完成，近似 `max(A,B)+调度开销`。如果瓶颈是共享的连接池或提供商并发上限，这个收益可能消失。计划和汇总若各需一次模型推理，还要将它们放回关键路径。第 9 周将对这些路径做统一对照。

## 读真实 Agent 的派发和等待

在 Codex 固定版本的 `spawn.rs` 找到 `handle_spawn_agent`，看模型工具调用如何进入派发流程以及响应如何标识目标；转到 `wait.rs` 找 `subscribe_status` 和 `timeout_at`。记录“发起成功”“收到终态”“等待超时”各自能证明什么。等待超时只说明等待者在截止前未拿到所需结果，不能单靠它推断远端任务已取消。[派发源码](https://github.com/openai/codex/blob/748ab55ca7de0b647d9a7a9d9a8e70e00f28666d/codex-rs/core/src/tools/handlers/multi_agents/spawn.rs) · [等待源码](https://github.com/openai/codex/blob/748ab55ca7de0b647d9a7a9d9a8e70e00f28666d/codex-rs/core/src/tools/handlers/multi_agents/wait.rs)

**口述自检。** 如果两馆的请求来自同一用户，为什么不让两个分支同时改共享答案？因为晚到的结果可能覆盖已核实事实。让每个分支交回独立记录，再由一处确定性合并，可以追踪每句结论来自哪个分馆。

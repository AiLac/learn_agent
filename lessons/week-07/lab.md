# 第 7 周 · 实践讲义｜任务规划、工具并行与子 Agent

## 输入与预算

用 E06、D07 的两张周六证据卡开始。此次先讨论“已给出并解析两馆”的比较子任务；若从原始提问端到端计时，要把识别或检索两馆的耗时也算入。为了和课程 3 次工具上限兼容，可让一次搜索返回两个匹配 ID，再做各一次证据查询，或在比较子实验中给两个方案相同的已解析 ID。

1. **2 小时，支持两馆比较。** 如需改造搜索，让同一个 `search_rooms` 能接收两个明确名称并各返回匹配项。给两种方案完全相同的工具。先跑单 Agent 实现，检查它是否查全两馆，是否在某家证据不足时仍写了排他性结论。
2. **2 小时，实现计划执行。** 让规划器返回两项任务，每项至少包含 `task_id`、`room_id`、`topic` 和比较条件。宿主检查 ID、去重、执行并汇总。规划可以先写成确定性的两步，再替换为模型规划，记录新增的模型耗时。
3. **2 小时，对照与故障。** 在同一证据版本上分别运行普通顺序工具、普通并发工具、模型决定下一步三种路径。给其中一路注入慢响应，在超时后返回已证实的部分，保留另一家标记。再用反向完成顺序测试，要求答案仍关联到同一个地点。
4. **2 小时，源码与复盘。** 比照 Codex 的派发、状态订阅与等待超时，为自己的实现画一张状态表。记录哪条路径耗时最短、哪条能处理非预期缺失，以及这两个结果是否同时出现。

```json
{"task_id":"room-2","room_id":"D07","topic":"hours","month":11,"weekday":"SATURDAY","local_time":"19:00","scope":"学生自修室"}
```

**参考判定。** 两馆资料齐全时，应指出 E06 符合，D07 按常规表已关闭，并分别引用。D07 超时时，可以说“已核实花园街符合；薄扶林尚未核实”，不应说“薄扶林没有开放”。故障恢复后重跑，应能填回第二个分支。

**选修。** 将每馆核验交给一个有独立模型交互的只读子 Agent。对普通工具并行与双子 Agent，分开记录模型调用、工具调用、总 token、分支耗时与最终正确性。只有实际启动并取得执行轨迹才能写成子 Agent 实验。

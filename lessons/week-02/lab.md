# 第 2 周 · 实践讲义｜把语义召回与事实查证分开

## 老师先融合一组候选

假设两路的前两名分别是关键词 [E06,E01]、向量 [E01,D07]。取 k=60，从空分数字典开始：关键词第一名 E06 加 1/61，E01 加 1/62；向量第一名 E01 再加 1/61，D07 加 1/62。最后 E01≈0.03252、E06≈0.01639、D07≈0.01613。这是为了检验融合实现而构造的名次，不能当成模型实测。

用这组输入写一个脱离模型的 Java 单测，预期顺序 [E01,E06,D07]。再让关键词与向量通路都只返回 E06，检验输出仍只有一条。通过这两步再换成真实向量结果；若这时表现仍差，你已经能先排除名次融合的一类错误。

## 输入和产出

复用上周 36 条记录、4 道开发题与本地检索函数。封存留出题后再调参。本周要得到两份可比较的检索结果，以及一个固定顺序生成简介的基线。再补 4 道开发题，累计 8 道。

## 1. 建证据卡（2 小时）

从[官方自修室时间表](https://www.hkpl.gov.hk/tc/locations/opening-hours-04.html)整理花园街 E06、油麻地 E01、薄扶林 D07 的普通 11 月时段，保留分馆、服务区域、原页的小节或表格行、核对日期。用同一页分别查普通工作日、周末；特别日期另作范围标记。可参考以下局部记录。字段是课程格式，时段来自官方资料。

```json
{"id":"E06-nov-sat","room_id":"E06","scope":"学生自修室","topic":"hours","month":11,"day":"SATURDAY","interval":["09:00","20:00"],"exceptions":"限普通周六","source":"https://www.hkpl.gov.hk/tc/locations/opening-hours-04.html","locator":"一至二月及六至十二月／花園街／星期六"}
```

## 2. 跑两路检索（3 小时）

用同一段名称、地区、地址和带来源的描述建立两个索引。第一路可用现成 BM25 或有明确排序规则的关键词打分，保留简单同义词。第二路用同一中文 embedding 模型分别编码查询和文档，缓存 36 个文档向量。核对维数、避免零向量除零，将有效的余弦结果排序。两路各返回候选 ID 和名次，再用理论讲义的公式融合；并列按 ID 排。跑“花园街”“油尖旺温书”“想在薄扶林晚点复习”，查看前五名。时间作为待查条件另记。

## 3. 完成固定流程（2 小时）

检索一次，给前两名分别取一次当前主题的证据，无第二名时只取一家。即使同一存在性问题的证据不全，也保留候选并标记可核实范围。把问题、候选 ID 和已取回的证据卡交给模型；输出每个地点的两句简介及引用 ID。查询和证据不足时允许给出明确的未知项。记录每步输入、结果及调用数量。这条路径要留到第 4 周作对照。

## 4. 核对结果（1 小时）

| 自测输入 | 验收关注点 |
| --- | --- |
| 只给花园街的地址记录 | 简介可给地址；未取到时段时不得断言周六晚开放。 |
| 同馆，增加周六时段证据 | 能解释普通 11 月周六 19:00 符合，引用对应周六证据。 |
| 向量路把另一家馆排得很高 | 输出两路排名和共享字段；先检查歧义、同义词和匹配字段，再决定是否改参数。 |

保留逐题的关键词前五、向量前五、融合前五和人工相关性。先写“哪道题的哪家馆升降了几位”，再谈是否改善；三家有详情的馆不能代表其余场馆均无相应服务。
